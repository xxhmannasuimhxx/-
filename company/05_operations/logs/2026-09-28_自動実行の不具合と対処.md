# 記録：Routine が2週間、空振りしていた（2026-09-28）

## 何が起きたか

9/15 に設定した Routine（月曜 `/kickoff`／金曜 `/weekly`）が、
**4回すべて「成功」と記録されながら、成果物を1つも残していなかった。**

| 発火日 | 記録上の状態 | 実行時間 | 実際の成果 |
|---|---|---|---|
| 9/18 金 | SUCCEEDED | — | なし |
| 9/21 月 | SUCCEEDED | — | なし |
| 9/25 金 | SUCCEEDED | 約28秒 | なし |
| 9/28 月 | SUCCEEDED | 約32秒 | なし |

main ブランチへのコミットは 9/17 の `24acaea` で止まっていた。

## 原因

**自動実行されたセッションにはリポジトリがクローンされていなかった。**
（Routine の設定を確認すると `sources: []`。環境は継承するが、リポジトリは付いてこない）

そして手順の冒頭に、こう書いてしまっていた：

> `company/` が存在しない場合は `git fetch origin main && git checkout main` で切り替える。
> **それでも存在しない場合は、その旨だけを報告して終了してください。**

git リポジトリ自体が無いので `git fetch` も失敗する。
結果、**毎回この逃げ道を通って30秒で正常終了し、「成功」と記録されていた。**

## なぜ気づけなかったか

- 完了通知は「何かあったとき」に届く設定だった。**何もせず終わった回は静かに終わる**
- 記録上の `SUCCEEDED` は「セッションが起動して終了した」の意味でしかない。
  **成果物の有無は見ていない**

## 対処（実施済み）

1. 手順の冒頭を「無ければ**自分でクローンする**」に変更
   `git clone https://github.com/xxhmannasuimhxx/-.git madoka && cd madoka && git checkout main`
   （このリポジトリは認証なしで clone / push ともに通ることを確認済み）
2. **「無いことを理由に黙って終了する」を禁止。** 失敗時は何を試して何が失敗したかを報告させる
3. **終了前の自己点検を必須化。** `git log` / `git status` でプッシュ完了を確認し、
   何も残せなかった場合は「成果物を残せませんでした」と明示させる
4. 代表待ちが何週も動いていない場合、同じ依頼を繰り返さず
   **タスク設計の問題として粒度を割り直す**ルールを追加

## 学び（今後の設計原則）

> **「成功」の定義を、セッションの終了ではなく成果物の有無に置く。**

- 自動化には必ず**自己点検ステップ**を入れる（やったつもりを検出する）
- 逃げ道（「〜の場合は終了してよい」）を書くときは、**そこを通った事実が見える形**にする
- 静かな失敗は、失敗より高くつく。**2週間分の機会損失があった**

積まれていなければ、Routine を「このセッションに直接発火する方式」に切り替える。

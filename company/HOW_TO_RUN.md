# 動かし方 — この会社を「まわる状態」にする

> 結論：まわるかどうかは、やる気ではなく**3つの歯車が噛んでいるか**で決まります。
> ①どこから開いても会社が立ち上がる ②思いつきの入口が1つ ③週2回の定例。
> 代表の作業時間は **週30分** に収まる設計です。

---

## 歯車1｜起動 — 「開いたら会社がいる」状態にする

Claude Code は、**開いたフォルダにある `CLAUDE.md` を自動で読み込みます。**
つまり会社の実体は、このリポジトリのファイルそのものです。逆に言うと、
**ファイルが見えない場所からセッションを開くと、会社は存在しません。**

### ✅ 統合済み（2026-09-17 完了）

| 項目 | 状態 |
|---|---|
| 既定ブランチ | **`main`**（切替済み） |
| main の中身 | 会社一式 ＋ 講座スライド ＋ 発信の原稿システム ＋ 名刺 |
| 結果 | **どの端末・どのセッションから開いても、5人が立ち上がる** |

**以後の作業はすべて `main` で行います。** 成果物は必ずコミットしてプッシュすること
（コンテナは使い捨てのため、プッシュしていないものは消えます）。

#### 統合しなかったブランチ

| ブランチ | 理由 |
|---|---|
| `work-automation-opportunities` | スライド生成を `lib/` に部品化した改造案。**土台が旧版のスライド**で、`build_deck.js` を削除する構成のため、統合すると現行の内容が壊れる。採用するなら最新版へ当て直しが必要 |
| `health-tracking-app` | 用途未確認。代表の判断待ち（board #10） |

### 起動する3つの入口

| 入口 | やり方 | 向いている場面 |
|---|---|---|
| **PCのターミナル** | このフォルダで `claude` と打つ | がっつり作る日 |
| **ブラウザ** | claude.ai/code → リポジトリを選ぶ | 外出先・PCが無いとき |
| **スマホ** | Claude アプリ／ブラウザから同じく | 思いついた瞬間に投げる |

どれで開いても、`CLAUDE.md` が読まれて同じ5人が立ち上がります。

### 呼び出し方は2通り

```
/kickoff                    ← スラッシュコマンド（定型の仕事）
マキ、来週のリール3本考えて     ← 名前で指名（その人格で応答）
```

## 歯車2｜入口 — 思いつきの投げ先を1つにする

**入口が2つ以上あると、人は必ず投げるのをやめます。**

現在、入口になりうるものが2つあります。
- この会社の `/braindump` → `company/00_inbox/`
- `madoka-content-system` の `draft` スキル（「メモ：」で始めると原稿化）

この2つは競合ではなく、**役割が違うので繋ぐのが正解**です。

```
   思いついた
       ↓
   「メモ：〜」  ────→ [draft] 即・原稿になる（リール/メルマガ/キャプション）
       ↓                    ＝ 発信したい単発のネタ
   「/braindump」 ───→ [アオイ] 戦略に分解 → 各部署 → タスク化
                            ＝ 企画・悩み・決めごと
```

**判断に迷ったら `/braindump` に投げれば、アオイが `draft` へ回します。**
迷う時間をゼロにするのが目的です。

## 歯車3｜記憶 — セッションは消える。ファイルだけが残る

ここが**この仕組みで一番大事な原理**です。

> Claude Code のセッションは、閉じると記憶がなくなります。
> **次のセッションが覚えているのは、ファイルに書かれたことだけ。**

だから `CLAUDE.md` の「口頭の長文で返さない。成果物は必ずファイルに書き出す」は、
お行儀の話ではなく **会社の生命線**です。チャットで消えた良いアイデアは、存在しなかったのと同じ。

| 残す場所 | 何が残るか | 効果 |
|---|---|---|
| `_shared/` | 理念・ペルソナ・商品・KPI | 毎回説明しなくてよくなる |
| `05_operations/tasks/board.md` | 進行中の仕事 | 「あれどうなった？」が消える |
| `05_operations/logs/` | 週次レビュー・講座の振り返り | 判断が積み上がる |
| `01_management/` | 戦略メモ | 同じ議論を二度しない |

**育てば育つほど、指示が短くて済むようになります。** それが「まわる」の正体です。

## 本当に「24時間働く」状態にする（自動化）

上記は「代表が開いたら動く」状態です。ここからもう一段上げられます。

**Routine（定期実行）を設定すると、代表が開かなくても Claude がセッションを立ち上げます。**

| 設定 | 何が起きるか |
|---|---|
| 月曜 7:00 に `/kickoff` | 起きたら戦略メモとタスクボードが更新済み |
| 金曜 17:00 に `/weekly` | 週次レビューが書き上がっている |
| 講座の3日前に運営チェック | ハルが抜け漏れを報告してくる |

代表がやるのは**朝それを読むだけ**。これが「デジタルスタッフが夜のうちに働いている」状態です。
→ 設定するかどうか、末尾の【要確認】1 で伺います。

## 止まるときの3パターンと処方箋

### ① 「まず理念を完璧に書いてから」で止まる（最頻出）
**処方：空欄のまま走らせてください。** 仮の理念でも、AIは動きます。
出てきた原稿を見て「これは違う」と感じた瞬間が、一番正確に理念を言語化できるタイミングです。
**先に埋めるのではなく、走らせて削る。**

### ② 「代表待ち」が溜まって全部止まる
**処方：ハルが3件超で警告します。** 5分で決められない粒度の質問が来たら、
「これ、案A/案Bにして」と返してください。決める作業自体をAIに整形させます。

### ③ 成果物は溜まるが、発信していない
**処方：タスクの完了条件を「作った」ではなく「出した」にする。**
board.md の状態を `完了` にできるのは、公開・送信まで終わったときだけです。

## 3. 提案する最小構成

### ★1｜数字を貯める表（`_shared/metrics.csv`）＋ `/weekly` での聞き取り

**何をするか**：毎週金曜の `/weekly` で、ハルが**チャットで最大5つ**数字を聞き、CSVに1行追記します。
数字は**人数と金額だけ**。名前は一切入れません。

```csv
週,メルマガ読者,IG フォロワー,説明会参加,個別相談,講座申込,入金額,時間_講座,時間_発信,時間_事務,時間_配信代行,ワクワク度
2026-10-23,237,,0,0,0,0,,,,,
```

| 項目 | 代表がどこを見るか | 所要 |
|---|---|---|
| メルマガ読者 | リザスト管理画面のトップ | 10秒 |
| IGフォロワー | プロフィール | 5秒 |
| 説明会・講座の申込数 **【改訂】** | **リザストのイベント一覧に出ている申込数**をそのまま（イベントごと） | 20秒 |
| 個別相談の数 | 覚えている数でよい | 5秒 |
| 入金額 | Stripe＋通帳（月1回でも可） | 30秒 |
| 時間（4区分） | 「だいたい何時間？」に感覚で答える | 30秒 |

**これで自動的にわかるようになること**
- 段ごとの転換率（読者→説明会→申込）＝ **導線のどこが詰まっているか**
- 期ごとの売上と、**1時間あたりの売上**（講座 vs 配信代行 の比較）
- ワクワク度と作業時間の関係（どの仕事が燃料を削っているか）

**【改訂】リザストのイベントを「段」として使う**
募集がすべてリザストのイベントなので、**イベント名がそのまま導線の段**になります。

| 段 | リザストのイベント（例） | 記録するもの |
|---|---|---|
| 入口 | 無料説明会・季節講座 | 申込数・参加数 |
| 本命 | スマイルおうち栄養士講座 9期 | 申込数・入金済み数 |

→ 「説明会に来た人のうち何人が9期に申し込んだか」が、**イベントごとの数を並べるだけ**で出ます。
新しい申込管理の仕組みは作りません。**リザストが申込台帳、こちらは集計値の控え**という分担です。

- イベント名に**期・種類がわかる名前**をつけておくと、数字が読みやすくなります（例：「【説明会】11/20」「【9期】本申込」）。命名ルールの案はこちらで作ります
- 申込者一覧のCSV出力など、リザスト側の機能の細部は【要確認】です（こちらは画面を見ていないため）。**CSVは個人情報を含むので、チャットやリポジトリには貼らない**でください。数だけで足ります

**実装**：`/weekly` コマンドに聞き取り手順を追記＋CSVを追記する短いスクリプト（または手で1行追記）。
`kpi.md` の空欄表は、CSVから**毎週自動で書き換える**ようにします。
**開発目安：2〜3時間。**

### ★2｜商品台帳（`_shared/offers.md` を整える）

主講座の情報はすでに十分です。足すのは**空白の3枠**だけ。

| 枠 | 埋める内容 | 埋め方 |
|---|---|---|
| 個別相談 | 価格・時間・申込方法・月の上限枠 | チャットで5問 |
| 無料説明会（★最優先の集客策） | 形式・頻度・定員・次回日程 | チャットで3問 |
| **企業・地域向け（新規）** | メニュー案3つ（例：社員向け栄養セミナー／自治体の親子食育講座／保育園の保護者会）・概算価格・実績【素材待ち】 | アオイが**たたき台を作り、代表は○×をつけるだけ** |

企業・地域向けは、**既存の6テーマ（248p）を90分版に切り出せば、そのまま商品になります**。
特に「2. 食べたものが体になるまで（腸）」「6. 朝ごはんと脳」は、企業研修・食育の需要と相性が良いと見ています。
**開発目安：1時間（ほぼ文書作業）。**

### ★3｜コンテンツ台帳（再利用のしくみ）

既存の `draft` スキルのフロントマターに**3項目だけ**足します。

```yaml
status: "draft"        # draft → published（既存）
published_at: ""       # 追加：出した日
channel: ""            # 追加：instagram / newsletter / 説明会 など
source_theme: ""       # 追加：講座テーマ番号（1〜6）。講座資料由来なら
```

そのうえで、**全原稿を読んで索引 `content_index.md` を自動生成するスクリプト**（Node、50行程度）を作ります。

- 「テーマ2（腸）の原稿で、まだ出していないもの」が一覧で出る
- 「半年前に出したメルマガ」をリール・ストーリーズに作り直す候補が出る
- 講座6テーマ → 発信ネタへの変換（board #6）の受け皿になる

**文章を書くのは代表、という聖域は変えません。** 台帳は「素材を探す時間」を消すためのものです。
**開発目安：2〜3時間。**

### ★4｜講座運営テンプレ（12月開講の前に）

開講日を1つ入れると、次を一括で出すテンプレート（またはスクリプト）。

- 全12回のライブ日程（約2週に1回）と、各回の前日リマインド文の**下書き**
  - **【改訂】** 説明会など**リザストのイベントで募集するものは、リマインドもリザストのイベント側の自動メール設定に任せる**前提にします（機能の有無と設定方法は【要確認】）。AIは**そこに貼る文面**を作るだけで、独自のリマインド送信の仕組みは作りません
  - 新しいイベントを立てるときの「**イベント作成チェックリスト**」（タイトル・定員・締切・決済方法・自動返信文・リマインド文）を用意し、毎回の設定漏れを防ぎます
- 運営チェックリスト（既存のハルのリストを日付つきで展開）
- プレミアム1on1（月1×6回）の枠表
- Routine に「各ライブの3日前に運営チェック」を追加（既に構想あり）

**送信は代表が行います。** AIは下書きと抜け漏れチェックまで。
**開発目安：2〜3時間。12月開講の2週間前までに。**

## 7. セキュリティ上の注意点

### 7-1. 個人情報は、このリポジトリに入れない（最重要）

| 置いてよい | 置いてはいけない |
|---|---|
| 人数・金額・率などの**集計値** | 受講生・相談者の**名前・連絡先・メールアドレス** |
| 匿名化した受講生の声（掲載許可済み） | **個別相談の内容・体調・病歴・服薬** |
| 商品・価格・原稿 | Stripeの顧客情報、振込名義 |

- **体調・病歴など健康に関する情報は、個人情報保護法の「要配慮個人情報」**にあたり得ます。
  分子栄養学カウンセリングの記録は特に該当しやすいため、**このリポジトリにもAIのチャットにも貼らない**運用を推奨します。
  （個別相談の記録は、現在お使いの方法のまま、リポジトリの外で管理してください）
- **git は一度コミットすると履歴に残ります。** 後から消しても過去の版から読めるため、「入れてから消す」は効きません。
- 企業・地域向けに広げると、**企業の従業員の健康データ**を扱う場面が出てきます。
  その場合は契約書で「集計値のみ受け取る」「個票は受け取らない」と定めるのが安全です。

### 7-2. 【要確認】このリポジトリの公開設定

記録に「認証なしで clone / push ともに通る」とあります（`logs/2026-09-28`）。
**リポジトリが公開（Public）になっている可能性があります。**
その場合、価格戦略・KPI・戦略メモ・名刺データなどが**誰でも読める状態**です。
外部に接続していないため、こちらでは確認していません。GitHubのリポジトリ設定で **Private** になっているかをご確認ください。
（Private であっても★1のCSVには集計値しか入れない設計にしています）

### 7-3. その他

- **APIキー（Stripe等）は使わない設計**にしています。将来連携する場合も、**読み取り専用の制限付きキー**のみ・`.env`（コミット対象外として設定済み）で管理
- GitHub・リザスト・Stripe・LINE は**二段階認証**を推奨
- **自動送信はしない。** メール・LINEはAIが下書き、送信は代表

# 仕事の進め方（ブレインダンプ → チーム分解 → 成果物）

> 代表の役割は **①ワクワクを吐き出す ②チェックして微調整する** の2つだけ。
> それ以外はすべてAIスタッフが引き受ける。

---

## STEP 1｜ブレインダンプ（壁打ち）

代表は、頭の中にあることを**整理せずそのまま**投げる。
音声入力・箇条書き・思いつきの断片、どれでもよい。整える作業はこちらの仕事。

**やり方（どちらでもOK）**
- そのままチャットに話す／貼る
- `company/00_inbox/` に `YYYY-MM-DD_思いつき.md` を作って書き殴る（テンプレ：`00_inbox/_braindump_template.md`）

**このときAIがやること**
1. 否定しない。**まず乗る。**
2. 断片を意味のかたまりに分類する（企画／悩み／不安／やりたい／決めたい）
3. 代表が言語化できていない「本当にやりたいこと」を1行で言い当てる
4. そのうえで、リスクや抜けを**最後に**添える

---

## STEP 2｜チームで自動分解

アオイ（経営戦略）が受け取り、各部署に振り分ける。

```
ブレインダンプ
   ↓
[アオイ] 売上インパクト × ワクワク度で評価 → 今週やること最大3つに絞る
   ↓
   ├─[マキ]  集客・SNS・導線     → リール企画／キャプション／導線改善
   ├─[リョウ] 販売・LP・コピー     → LP原稿／セールスメール／FAQ
   ├─[ノエル] 講座・記事・資料     → カリキュラム／原稿／スライド構成
   └─[ハル]  タスク・進行・運営    → board.md に登録／チェックリスト発行
```

**アオイの評価軸**

| | ワクワクする | ワクワクしない |
|---|---|---|
| **売上に効く** | ◎ 即やる | △ AIに丸投げできる形にしてからやる |
| **売上に効かない** | ○ 余白としてやる（燃料になる） | ✕ やらない |

---

## STEP 3｜成果物の自動生成

各担当が**完成形のファイル**を書き出す。構成案止まりは納品と認めない。

| 成果物 | 担当 | 保存先 |
|---|---|---|
| リール構成・キャプション | マキ | `02_marketing/` |
| 導線設計 | マキ | `02_marketing/導線設計.md` |
| LP原稿・セールスメール | リョウ | `03_sales/` |
| 講座カリキュラム・記事 | ノエル | `04_contents/` |
| タスク・チェックリスト | ハル | `05_operations/tasks/board.md` |
| 戦略メモ | アオイ | `01_management/` |

**代表がやること：開いて読む → 気になった箇所に一言コメントする。以上。**

---

## 定例（おすすめリズム）

- **月曜の朝5分**：`/kickoff` … 今週の3つを決める
- **金曜の夕方5分**：`/weekly` … KPI更新と来週の準備
- **思いついたとき**：`/braindump` … 吐き出す。整理はAIがやる

## スラッシュコマンド一覧

| コマンド | 内容 |
|---|---|
| `/braindump` | 思いつきを投げると、チームが分解してタスク化する |
| `/kickoff` | 今週やること最大3つを決める（アオイ主導） |
| `/meeting` | 5人全員の視点でひとつのテーマを検討する経営会議 |
| `/sns` | リール／投稿の企画とキャプションを完成形で出す |
| `/lp` | LP原稿を最後まで書き切る |
| `/weekly` | KPI更新・振り返り・来週の準備 |

定義は `.claude/commands/` にあります。

# 発信コンテンツの原稿化

髙落まどかさんの発信（食と生活リズム、子どもの食事）のための原稿を作る。
走り書きのメモを受け取り、内容に合った形式の原稿に整えてフォルダへ保存する。

読み手は、子どもの食事や生活リズムに悩む保護者。専門用語は噛み砕き、責める調子にはしない。

## 手順

1. **原文を `original/` に保存する。** 受け取ったメモをそのまま残す。整形も要約もしない。
2. **分類先を決める。** ユーザーが「メルマガで」等と指定していればそれに従う。
   指定がなければ下表から選び、なぜそこにしたかを一言添える。
3. **原稿を書き、該当フォルダに保存する。**
4. **保存先と要約を報告する。** 原稿の全文をチャットに貼り直さない（ファイルを見れば済む）。

複数の形式で欲しいと言われたら、その数だけ原稿を作ってよい。指定がなければ1つ。

## 分類先

| フォルダ | 適する内容 | 原稿の形式 |
| --- | --- | --- |
| `ideas/` | まだ形になっていない着想・企画の種。断片的で結論が出ていないもの | 見出しと箇条書き。何が引っかかったのか、どう展開できそうか。無理に結論づけない |
| `reels/` | 30〜60秒で伝えられる一つの気づきや実践方法 | 話し言葉。「フック（冒頭2秒）」「本編」「締め」の3見出し。本編は3〜4ステップ。テロップ案も添える |
| `stories/` | その日の出来事や短い問いかけ | 3〜5枚構成。1枚2〜3行。「1枚目」「2枚目」…と見出しを付ける。最後の1枚は質問スタンプやリンク導線の案 |
| `newsletter/` | 背景や理由まで掘り下げられるテーマ | 1行目に件名。本文600〜1200字。導入・本題・実践できる一歩・結び。読者一人に語りかける文体 |
| `captions/` | 画像や図解とセットで伝える投稿 | 冒頭1行のフック、本文（3〜5段落・改行多め）、行動を促す一文、末尾にハッシュタグ5〜10個 |

迷ったら、内容の完成度と話せる長さで決める。断片的なものは `ideas`、
短く話して伝わるものは `reels`、背景まで書き込めるテーマは `newsletter`。

## 原稿を書くときの約束

- メモの内容と意図をそのまま活かす。テーマを勝手に広げたり、別の話にすり替えたりしない。
- **メモに書かれていない栄養情報・数値・研究結果・エピソードを創作しない。**
  裏付けや実例が必要だと感じた箇所は、本文中に `[要確認]` と書いて残す。
- 断定しすぎない。「〜すべき」より「〜という手もあります」の温度で。
- 手直しなしで投稿できる状態まで仕上げる。

## ファイルの作り方

ファイル名は `YYYY-MM-DD-HHMMSS-<英小文字とハイフンのslug>.md`。
slug は内容を表す短い英語（例: `summer-breakfast-rhythm`）。

**時刻は必ず日本時間で記録する。** 実行環境が UTC のことがあるので、`date` は
そのまま使わずタイムゾーンを指定する。

```bash
TZ=Asia/Tokyo date +%Y-%m-%d-%H%M%S   # ファイル名用 → 2026-09-07-142458
TZ=Asia/Tokyo date +%Y-%m-%dT%H:%M:%S%:z  # フロントマター用 → 2026-09-07T14:24:58+09:00
```

原稿には YAML フロントマターを付ける。

```markdown
---
title: "朝ごはんが進まない日の一手"
category: "reels"
tags: ["朝ごはん", "生活リズム", "夏休み"]
summary: "食欲がない朝に試せる一手をまとめたリール台本。"
source_note: "original/2026-08-13-140908-asagohan.md"
status: "draft"
---

（本文）
```

`original/` に置く原文には `received_at`（日本時間）と `status: "raw"` だけ付ければよい。

## 保存したあと

コミットするかはユーザーに聞く。まとめて何本か作ったあとに一度コミットする方が履歴が読みやすい。
